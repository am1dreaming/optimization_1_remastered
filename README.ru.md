# Решение числовых ребусов: оптимизация (лабораторная работа № 2, вариант 1)

Функция `char *solve(const char *puzzle)` принимает ребус вида `SEND + MORE = MONEY`
и возвращает решение `9567 + 1085 = 10652` (или `NULL`, если ввод некорректен или решения нет).

Ограничения по заданию: заглавные латинские буквы, только `+`, от 2 до 7 слагаемых,
одна буква соответствует одной цифре, ведущие нули запрещены (одиночная буква может быть 0).

## Версии

| Файл | Что изменено | Тип оптимизации |
|---|---|---|
| `v0_baseline.c` | полный перебор размещений, на каждом листе выражение пересчитывается целиком | исходная версия |
| `v1_coeffs.c` | каждой букве заранее считается весовой коэффициент (±10^разряд); на листе — Σ коэф·цифра | машинно-независимая (вынос инвариантов) |
| `v2_incremental.c` | сумма накапливается по ходу спуска, лист проверяется за O(1) | машинно-независимая (снижение стоимости операций) |
| `v3_bounds.c` | отсечение ветви, если остаток суммы уже не может дать 0 (branch and bound) | алгоритмическая |
| `v3_order.c` | буквы перебираются по убыванию \|коэффициента\| — граница срабатывает с первых уровней | эвристика |
| `v4_columns.c` | поразрядный перебор по столбцам с переносом: столбец проверяется сразу, как только известны его буквы | алгоритмическая |
| `v5_forced.c` | цифра буквы результата не перебирается, а вычисляется: (сумма столбца + перенос) mod 10 | алгоритмическая |
| `v6_bitmask.c` | занятые цифры — битовая маска, свободные обходятся через «младший единичный бит» (`ctz`) | машинно-зависимая |

Общая часть (разбор, вывод, проверка ответа, тесты, замер времени, `main`) — в `rebus.h`;
каждая версия определяет только `solve_core()`.

## Сборка

### Windows (Visual Studio)
Нужны Visual Studio 2019 16.8+ (компонент «Разработка классических приложений на C++») и CMake
(входит в VS). В «Developer PowerShell for VS»:
```powershell
cmake -S . -B build
cmake --build build --config Release
```
Исполняемые файлы окажутся в `build\Release\`.

### Windows (MinGW / MSYS2)
```powershell
cmake -S . -B build -G "MinGW Makefiles"
cmake --build build
```

### macOS
Нужны Xcode Command Line Tools (`xcode-select --install`) и CMake (`brew install cmake`):
```bash
cmake -S . -B build
cmake --build build
```
Без CMake: `make` (бинарники в `build/`).

### Linux
```bash
cmake -S . -B build && cmake --build build      # или просто: make
```

## Запуск

```bash
./build/v6_bitmask                         # решить встроенные тесты
./build/v6_bitmask "BE + BE = MOO"         # свой ребус
./build/v6_bitmask -b                      # бенчмарк
```
Ключи бенчмарка: `-t МС` — минимальное время замера одного ребуса (по умолчанию 200, `0` — один прогон), `-f ФАЙЛ` — ребусы из файла по одному в строке.
Формат бенчмарка: `ребус<TAB>мс на одно решение<TAB>узлов перебора<TAB>OK/FAIL`.
Каждый ребус решается повторно не менее 200 мс, время усредняется; ответ проверяется
независимой функцией `verify`. Код возврата ≠ 0, если хоть одна проверка не прошла.

## Профилирование

- **Linux / MinGW (gcc):** `cmake -S . -B build-prof -DREBUS_PROFILE=ON && cmake --build build-prof`,
  затем `./build-prof/v0_baseline -b` и `gprof build-prof/v0_baseline gmon.out > profile.txt`.
  Или без пересборки: `perf stat ./build/v0_baseline -b`.
- **macOS:** Xcode → Open Developer Tool → Instruments → Time Profiler (или `xctrace record --template "Time Profiler" --launch -- ./build/v0_baseline -b`).
- **Windows:** Visual Studio → Отладка → Профилировщик производительности → «Использование ЦП».

Во всех версиях есть счётчик `nodes` (число вызовов `search`) — он не зависит от машины
и показывает, насколько оптимизация сокращает перебор.

## Сложность

n — число различных букв (≤ 10), L — суммарная длина выражения, R — длина результата.

- v0: O(A(10, n) · L), где A(10, n) = 10!/(10−n)! — число размещений; на каждом листе пересчёт выражения.
- v1: O(A(10, n) · n) — на листе n умножений вместо разбора строк.
- v2: O(A(10, n)) — лист за O(1).
- v3–v6: в худшем случае та же оценка O(A(10, n)), но отсечения на практике сокращают число узлов
  на 2–4 порядка (см. `nodes_total.png`); v4–v5 дополнительно отсекают по каждому столбцу,
  v5 убирает ветвление для букв результата (≈ в 10 раз меньше ветвей на такой уровень),
  v6 уменьшает только стоимость одного узла.
